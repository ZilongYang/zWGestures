# 界面多语言（中/英）+ 手势名中文化 —— 实施方案

> **状态**：2026-10-06 提交作者批准。**分四期实施**，第 1 期先给作者看效果再继续。
> 正文是批准时的方案，**原样存档、不再更新**；实施结果与差异见文末补记。
> 相关的成本评估原文在 [`ROADMAP.md`](ROADMAP.md) 第 15 节。
> 发版打勾清单另见 [`RELEASE-CHECKLIST-0.3.0.md`](RELEASE-CHECKLIST-0.3.0.md)（第 4 期时建）。

## 0. 用户要求（2026-10-06）

1. **先做多语言 / 英文版**（“突然忘了英文版，那先做多语言、英文版吧”）。
2. **手势名中文化**：现在大部分手势名是英文的（`Close`、`Web Search` 等），要改成中文。
3. **404 页排在英文版之后**。

## 1. 现状盘点（2026-10-06 实测）

| 位置 | 用户可见文案 | 说明 |
|---|---|---|
| `zWGestures/`（App target） | **235 条**（去重后） | 20 个文件；另有 28 条纯日志文案 |
| `ZWGCore/Sources`（展示层与模型） | **85 条**（去重后） | 主要是 `WGIntentDisplay`、`WGConfig`、`CommandEditorModel`、`WGEdgeCorner`、`GestureEditorModel` |
| `ZWGCore/Tests` | 661 行含中文字面量 | 大部分是测试名与诊断信息，不全是文案断言 |

- `project.yml`：`CFBundleDevelopmentRegion: zh-Hans`、`CFBundleLocalizations: [zh-Hans]`、
  `NSAppleEventsUsageDescription` 是中文。
- 出厂默认手势包（`zWGestures/Resources/Defaults/gestures.json`）名字来自原版的
  `zh_CN.lproj/tr_bootstrap.json`（生成脚本 `scripts/make-default-gestures.py`），
  其中仍有混排的 `Web 搜索`、`粘贴并 Enter`、`Home 键` 等。
- 原版 App 仍装在本机，其 `Resources/` 下有英文出厂 `gestures.json` 与 `zh_CN.lproj/`
  （仅作构建期取名用，与第 16 节现有做法一致）。

## 2. 方案

### 2.1 本地化机制：自建一层薄的，不引入 String Catalog

新 `ZWGCore/Localization/`：

- `WGLanguage`（`.zhHans` / `.en`）与 `WGLanguagePreference`（`.system` / `.zhHans` / `.en`），
  `resolve(preference:system:)` 决定实际语言（偏好优先，其次系统首选语言）。
- `L10n.Key`：enum（`CaseIterable`），配一个 **`switch` 形式的对照表**
  `case .settingsSearchPlaceholder: ("搜索手势…", "Search gestures…")` —— 用 switch 而不是字典，
  是为了**漏一条就编译不过**。
- `L10n.text(_:)` / `L10n.format(_:_:)`：带参数的用 `String(format:)`（占位符两语言必须一致）。
- `L10n.setLanguage(_:)`：当前语言放在锁里；读便宜、线程安全。

**不选 `.xcstrings` 的理由**：① 自建表能单测（漏翻、英文表残留中文、占位符一致性），
`.xcstrings` 只能肉眼；② 本机 Xcode 工具链已出过两次插件级故障（宏插件直接崩），不加新构建环节；
③ 语言可显式切换，作者两种都能立刻看。代价是 320 个调用点要改（翻译工作量相同）。

唯一必须用真 `.lproj` 的是 Info.plist 的 `NSAppleEventsUsageDescription`：
加 `zh-Hans.lproj` / `en.lproj` 两份 `InfoPlist.strings` + `CFBundleLocalizations: [zh-Hans, en]`。

### 2.2 展示层不搬家、不做 locale 注入

`WGIntentDisplay`、`WGCommand.summary` 与各模型里的用户可见文案**直接调 `L10n`** ——
ZWGCore 知道「语言」，但不知道「UI」。公开 API 不变，现有测试基本不用改
（测试进程里把语言钉成 zh）。tap 线程不读 `L10n`（轨迹上显示的是配置里的**手势名**，
那是用户数据，不是界面文案）。

### 2.3 手势名中文化（作者 2026-10-06 选定：**显式动作 + 启动时问一次**）

手势名是**配置数据**，本地化层不碰它。三条：

1. **出厂默认包做两份**：`Defaults/gestures.json`（中文名，现有）+ `gestures.en.json`
   （原版自带的英文名），按界面语言播种。新增测试钉住**两份包除 `Name` 外逐键一致**
   —— 笔画与命令必须完全相同，否则就是行为差异。
2. **已导入的英文名配置**：菜单栏加一项「把英文手势名改为中文」，并在启动时若发现
   已知英文名 ≥ 5 条就**弹一次询问**（一键改 / 忽略）；用仓库已有的那张译名表，
   **改之前自动备份**，绝不静默改写用户的配置。
3. 键名固定为粗体：`Enabled`、`inheritsGlobal`、`Language` 这类扩展键都**只在非默认值时写出**，
   以保住 `ConfigTests` 的「重新编码后与原文件逐键一致」守卫。

### 2.4 语言偏好

`prefs.json` 增 `Language`（`system` 默认 / `zh-Hans` / `en`），沿用 2.3 第 3 条的写出规则。
偏好设置界面加「界面语言」一项，切换后**菜单栏与窗口立刻重建**
（`NSMenu` 是静态的，SwiftUI 视图需要重新读文案 —— 这是本期最容易出「切了没生效」的地方）。

### 2.5 分期

| 期 | 内容 | 可验收的现象 |
|---|---|---|
| **1** | 机制 + 语言偏好 + **菜单栏 + 手势列表**（含列表里显示的形状描述与命令摘要） | 切一次语言，菜单与手势列表立刻变英文 |
| 2 | 其余调用点：命令编辑器、偏好各页、各类弹窗与错误提示、应用目标管理 | 设置界面全英文 |
| 3 | 手势名中文化 + 两份默认包 | `Close` / `Web Search` 变「关闭 / 网络搜索」 |
| 4 | Info.plist 本地化、文档、发版准备（0.3.0） | 系统权限弹窗也跟语言走 |

### 2.6 明确不做

- **日志（`Log.*`）不翻**，调试面板同理 —— 那是开发排查用的，翻译只会翻倍工作量。
- 不改 `site/index.html`（自带中英切换）；**404 页排在这一切之后**。
- 不做第三语言、不做 RTL。
- **不打包原版任何资源**：只在构建期用它的名字表生成两份默认包的**名字**（与第 16 节做法一致），
  `tr_bootstrap.json` 不进产物。

## 3. 测试与验收

- 新增 `L10nTests`：`allCases` 里每条都有两种语言（switch 保证）、**英文表里没有中日韩字符**、
  中英两份的 `%` 占位符一一对应、`resolve` 的三种情形（跟随系统 / 强制中文 / 强制英文）、
  未知系统语言回落到英文。
- `PreferencesModel` / `ConfigTests`：新增 `Language` 键后，**默认值不写出**、逐键一致守卫仍然过。
- 作者实机验收：菜单栏、设置界面各页、命令编辑器、手势编辑器、各类弹窗、权限弹窗；
  两种语言各过一遍（第 1 期只看菜单栏 + 手势列表）。

## 4. 风险

- 最容易漏的是**动态拼出来的句子**（「其中已禁用 N 条」、各类错误描述）—— 靠 `CaseIterable`
  与占位符测试兜。
- `Log.*` / `print` 里混着的少量 UI 文案需要逐个甄别（盘点时已按 `Log.` 过了一轮）。
- 语言切换要重建菜单与窗口；`NSMenu` 的静态标题只在初始化时设过一次，必须改成每次刷新都重设。
- 320 条改造会碰一批断言中文文案的测试 —— 处理原则：**测试里把语言钉成 zh**，不改成断言英文。
